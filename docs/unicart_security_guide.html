02 Stateless Authentication & Dual-Token Lifecycle

Traditional session-based authentication requires in-memory state or sticky sessions, introducing catastrophic bottlenecks when horizontally scaling. UniCart uses a hardened Dual-Token Stateless Architecture combining short-lived in-memory access tokens with cryptographically protected rotating refresh cookies.

2.1 Dual-Token Separation of Concerns

  • Access Token (15-Minute Expiry): Held exclusively in frontend JavaScript client memory (React state / closure). It is never stored in localStorage or sessionStorage, completely immunizing the user against token extraction via Cross-Site Scripting (XSS).
  • Refresh Token (7-Day Expiry): Transmitted exclusively via a browser cookie flagged with httpOnly, Secure, SameSite=Strict, and scoped strictly to path: '/api/v1/auth'. JavaScript cannot read this cookie, eliminating XSS token harvesting.
  • Database Hashing: Raw refresh tokens are never stored in the database. Only their cryptographic SHA-256 hash is persisted. A database snapshot leak cannot compromise active user sessions.
server/src/utils/token.ts TypeScript 
// Cryptographic token generation & cookie hardening
export function signAccessToken(payload: AccessTokenPayload): string {
  const options: SignOptions = {
    expiresIn: env.JWT_ACCESS_TTL as SignOptions['expiresIn'], // 15m
    algorithm: 'HS256'
  };
  return jwt.sign(payload, env.JWT_ACCESS_SECRET, options);
}

export function generateRefreshToken(): { rawToken: string; tokenHash: string } {
  // Generate 64 cryptographically secure random bytes
  const rawToken = crypto.randomBytes(64).toString('hex');
  // Hash with SHA-256 before database insertion
  const tokenHash = crypto.createHash('sha256').update(rawToken).digest('hex');
  return { rawToken, tokenHash };
}

export function getRefreshTokenCookieOptions(): CookieOptions {
  const sameSite = (env.COOKIE_SAME_SITE as CookieOptions['sameSite']) || 'strict';
  return {
    httpOnly: true,      // Completely inaccessible to document.cookie (No XSS theft)
    secure: sameSite === 'none' ? true : env.COOKIE_SECURE || env.NODE_ENV === 'production',
    sameSite,            // Strict cross-site boundary (Zero CSRF vulnerability)
    path: '/api/v1/auth', // Isolated scope: browser will NOT transmit cookie on catalog queries
    maxAge: env.REFRESH_TOKEN_TTL_DAYS * 24 * 60 * 60 * 1000
  };
}

2.2 Automatic Token Reuse Detection & Revocation Cascade (A07)

If an attacker manages to intercept an in-flight refresh token and attempts to replay it after the legitimate client has rotated it, UniCart's Family Reuse Detection triggers immediately. Every session belonging to that family is instantaneously revoked, terminating both the attacker and victim sessions to protect user assets.

server/src/modules/auth/auth.service.ts TypeScript 
// Automatic token reuse attack detection
const tokenHash = hashToken(rawRefreshToken);
const tokenRecord = await RefreshToken.findOne({ tokenHash });

if (!tokenRecord) {
  throw ApiError.unauthorized('Invalid refresh token', 'INVALID_REFRESH_TOKEN');
}

// REUSE DETECTION: If token was already revoked, an attacker or victim is replaying!
if (tokenRecord.revokedAt) {
  // Invalidate every token in the entire token family immediately
  await RefreshToken.updateMany(
    { familyId: tokenRecord.familyId },
    { revokedAt: new Date() }
  );

  await AuditLog.create({
    actorId: tokenRecord.userId,
    action: 'auth.refresh.reuse_detected',
    target: tokenRecord.userId.toString(),
    ip,
    meta: { familyId: tokenRecord.familyId, severity: 'HIGH_SECURITY_ALERT' }
  });

  throw ApiError.unauthorized(
    'Revoked refresh token reuse detected. All sessions in this family have been terminated.',
    'TOKEN_REUSE_DETECTED'
  );
}
Instant Global Invalidation via tokenVersion
What happens if an admin changes a user's password or revokes an account? Checking access tokens usually takes 15 minutes to expire. UniCart includes a tokenVersion: number inside both the User document and the JWT payload. The authenticate middleware compares user.tokenVersion !== decoded.tokenVersion. Incrementing user.tokenVersion revokes every active access token globally within 0 milliseconds!

03 Argon2id Password Cryptography & Brute-Force Defense

Legacy systems frequently rely on MD5, SHA-256, or poorly tuned bcrypt. UniCart utilizes Argon2id, the winner of the Password Hashing Competition (PHC), which provides maximum resistance against both GPU-accelerated side-channel attacks and specialized ASIC cracking hardware.

3.1 Cryptographic Parameters

  • Algorithm: argon2id (hybrid time-memory trade-off resistance)
  • Memory Cost: 65,536 KB (64 MB) — forces attackers to consume prohibitive RAM per hash attempt.
  • Time Cost: 3 iterations — mathematically tuned to take ~60ms on modern server CPUs, fast enough for human UX but completely intractable for parallel dictionary attacks.
  • Parallelism: 1 thread — deterministic thread allocation per process.
server/src/models/User.ts TypeScript 
// Automated Argon2id pre-save hook
userSchema.pre('save', async function (next) {
  if (!this.isModified('password') || !this.password) {
    return next();
  }

  try {
    this.password = await argon2.hash(this.password, {
      type: argon2.argon2id,
      memoryCost: 65536, // 64 Megabytes per hash
      timeCost: 3,       // 3 passes
      parallelism: 1
    });
    next();
  } catch (err) {
    next(err as Error);
  }
});

// Constant-time verification helper
userSchema.methods.verifyPassword = async function (candidate: string): Promise<boolean> {
  if (!this.password) return false;
  return argon2.verify(this.password, candidate);
};

3.2 Progressive Account Lockout Mechanism

To prevent automated credential stuffing and dictionary attacks, UniCart monitors failed authentication attempts. If five consecutive invalid passwords are submitted, the account enters a hardened lockout state for 15 minutes.

server/src/modules/auth/auth.service.ts TypeScript 
// Check if account is locked prior to verification
if (user.isLocked()) {
  const remainingMinutes = Math.ceil((user.lockUntil!.getTime() - Date.now()) / 60000);
  throw ApiError.unauthorized(
    `Account is temporarily locked. Try again in ${remainingMinutes} minutes.`,
    'ACCOUNT_LOCKED'
  );
}

// Constant-time password validation
const isValid = await user.verifyPassword(input.password);
if (!isValid) {
  user.failedLogins = (user.failedLogins || 0) + 1;
  // Lock account if threshold exceeded (5 failed logins)
  if (user.failedLogins >= 5) {
    user.lockUntil = new Date(Date.now() + 15 * 60 * 1000); // 15 minute lock
    await AuditLog.create({
      actorId: user._id,
      action: 'auth.account.locked',
      ip,
      meta: { email: user.email, failedAttempts: user.failedLogins }
    });
  }
  await user.save();
  throw ApiError.unauthorized('Invalid credentials', 'INVALID_CREDENTIALS');
}

04 Google OAuth 2.0 Identity Federation

Client-side authentication frameworks frequently make the catastrophic mistake of passing user emails directly from the frontend to the backend after Google sign-in. This allows an attacker to forge requests claiming to be any email address.

Crucial Architecture Rule
UniCart never trusts user metadata sent by the frontend. The frontend sends only the raw cryptographic Google ID token (JWT) signed by Google. The UniCart backend downloads Google's public JSON Web Key Sets (JWKS) via google-auth-library, validates the cryptographic RSA signature, and verifies that the audience matches env.GOOGLE_CLIENT_ID.
server/src/modules/auth/auth.service.ts TypeScript 
// Cryptographic server-side Google token verification
const googleClient = new OAuth2Client(env.GOOGLE_CLIENT_ID);

async googleAuth(idToken: string, ip?: string): Promise<AuthResult> {
  let email: string;
  let name: string;
  let googleId: string;
  let avatar: string | undefined;

  try {
    // Authenticate signature against Google's live public certs & verify audience
    const ticket = await googleClient.verifyIdToken({
      idToken,
      audience: env.GOOGLE_CLIENT_ID
    });
    const payload = ticket.getPayload();

    if (!payload || !payload.email) {
      throw ApiError.unauthorized('Invalid Google ID token payload', 'INVALID_GOOGLE_TOKEN');
    }

    email = payload.email.toLowerCase();
    name = payload.name || email.split('@')[0];
    googleId = payload.sub; // Unique immutable Google user identifier
    avatar = payload.picture;
  } catch (err) {
    throw ApiError.unauthorized('Google authentication failed: invalid token', 'INVALID_GOOGLE_TOKEN');
  }

  // Atomically locate or provision user record
  let user = await User.findOne({ $or: [{ googleId }, { email }] });

  if (!user) {
    user = new User({ name, email, googleId, avatar, role: 'customer' });
    await user.save();
    await AuditLog.create({ actorId: user._id, action: 'auth.register.google', ip });
  } else {
    // Securely link Google identity to existing account if email matches
    if (!user.googleId) user.googleId = googleId;
    if (avatar && !user.avatar) user.avatar = avatar;
    await user.save();
  }

  // Issue UniCart dual-token pair with session family
  return this.issueSession(user, ip);
}

05 Authorization, RBAC & IDOR Elimination

Insecure Direct Object References (IDOR) remain the #1 vulnerability on e-commerce platforms, enabling attackers to view other customers' orders or cancel shipments simply by modifying an ID parameter in the URL.

5.1 Multi-Layered Ownership Enforcement

UniCart strictly enforces an invariant: A user may only interact with resources they explicitly own, unless they hold the verified role of admin.

server/src/modules/orders/order.service.ts TypeScript 
// Strict ownership check (IDOR Prevention) on Order Operations
async payOrder(userId: string, orderId: string, paymentRef?: string): Promise<IOrder> {
  const order = await Order.findById(orderId);
  if (!order) {
    throw ApiError.notFound('Order not found', 'ORDER_NOT_FOUND');
  }

  // IDOR ENFORCEMENT: Reject immediately if requesting user is not resource owner
  if (order.userId.toString() !== userId) {
    throw ApiError.forbidden('You lack permissions to access this order', 'FORBIDDEN');
  }

  // State machine verification & idempotent payment execution
  if (order.status === 'paid') return order;
  order.status = 'paid';
  order.paymentRef = paymentRef || `pay_${uuidv4().substring(0, 8)}`;
  await order.save();
  return order;
}

5.2 Granular Role-Based Access Control (RBAC)

Admin capabilities (product catalog mutation, category CRUD, system inventory modifications) are shielded behind the authorize('admin') middleware.

server/src/middleware/rbac.ts TypeScript 
// Role validation middleware
export function authorize(...allowedRoles: string[]) {
  return (req: Request, _res: Response, next: NextFunction): void => {
    if (!req.user) {
      return next(ApiError.unauthorized('Authentication required', 'UNAUTHENTICATED'));
    }

    if (!allowedRoles.includes(req.user.role)) {
      return next(
        ApiError.forbidden(
          `Access forbidden. Requires one of: [${allowedRoles.join(', ')}]`,
          'FORBIDDEN'
        )
      );
    }
    next();
  };
}

06 Input Validation, Sanitization & DoS Defense

Every byte entering the UniCart Express pipeline is inspected, normalized, sanitized, and type-checked before reaching business controllers.

6.1 Strict Zod Schema Parsing & Unknown Field Stripping

UniCart schemas strictly enforce type bounds and reject unauthorized properties using .strict(), preventing mass assignment vulnerabilities.

server/src/middleware/validate.ts TypeScript 
// Composite request validation middleware
export function validate(schema: RequestValidationSchema | ZodTypeAny) {
  return async (req: Request, _res: Response, next: NextFunction): Promise<void> => {
    try {
      if ('body' in schema || 'query' in schema || 'params' in schema) {
        const composite = schema as RequestValidationSchema;
        if (composite.body) req.body = await composite.body.parseAsync(req.body);
        if (composite.query) req.query = await composite.query.parseAsync(req.query);
        if (composite.params) req.params = await composite.params.parseAsync(req.params);
      } else {
        req.body = await (schema as ZodTypeAny).parseAsync(req.body);
      }
      next();
    } catch (error) {
      next(error); // Centralized error handler maps ZodError into HTTP 422
    }
  };
}

6.2 Neutralizing NoSQL Injection & Parameter Pollution

An attacker might transmit JSON with MongoDB query operators such as {"email": {"$gt": ""}, "password": {"$ne": null}} to bypass authentication. UniCart sanitizes all incoming keys, replacing any key beginning with $ or containing a . with an underscore.

server/src/app.ts TypeScript 
// 1. Strip MongoDB query selector injection attempts
app.use(mongoSanitize({ replaceWith: '_' }));

// 2. Guard against HTTP Parameter Pollution (e.g. ?role=admin&role=customer)
app.use(hpp());

// 3. Scoped payload size limits (DoS Prevention)
// Admin image uploads are allowed up to 20MB exclusively on admin endpoints
app.use('/api/v1/admin', express.json({ limit: '20mb' }));
app.use('/api/v1/admin', express.urlencoded({ extended: true, limit: '20mb' }));

// Public customer endpoints retain a strict 10kb ceiling
app.use(express.json({ limit: '10kb' }));
app.use(express.urlencoded({ extended: true, limit: '10kb' }));

07 Multi-Tier Rate Limiting & Docker Hardening

7.1 Edge & Application Rate Limiting

UniCart protects against distributed Denial of Service (DDoS) and credential stuffing via a dual-tiered rate limiter:

  • Edge Tier (Nginx): limit_req_zone $binary_remote_addr zone=api_limit:10m rate=10r/s; drops excess traffic at the reverse proxy before it reaches Node.js memory.
  • Application Tier (Redis-Backed): Express uses rate-limit-redis across all replicas. The auth endpoints restrict traffic to 5 attempts per 15 minutes per IP, while general endpoints allow up to 300 req/min.
server/src/middleware/rateLimit.ts TypeScript 
// Distributed Redis-backed rate limiting
export const authRateLimiter = createRateLimiter({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 5,                   // 5 attempts max
  prefix: 'auth',
  message: 'Too many authentication attempts. Please try again in 15 minutes.'
});

7.2 Container Security Hardening (Docker)

Containers running as root represent a severe container breakout risk. UniCart's multi-stage Docker build drops root privileges, strips development build tooling, and executes as unprivileged user node.

server/Dockerfile Dockerfile 
# Stage 1: Build TypeScript in isolated builder
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json tsconfig*.json ./
RUN npm ci
COPY src/ ./src/
RUN npm run build

# Stage 2: Production Runner (Hardened & Non-root)
FROM node:20-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production PORT=5000

# Strip devDependencies completely
COPY package*.json ./
RUN npm ci --omit=dev && npm cache clean --force

# Copy compiled JavaScript output
COPY --from=builder /app/dist ./dist

# Hardening: Switch execution to unprivileged node user
RUN chown -R node:node /app
USER node

# Live healthcheck probing internal endpoint
HEALTHCHECK --interval=15s --timeout=5s --start-period=10s --retries=3 \
  CMD wget -qO- http://localhost:5000/health/live || exit 1

CMD ["node", "dist/server.js"]
